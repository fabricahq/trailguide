# Testing

**Group ID:** `practices/testing`

**Description:** Spend test effort where bugs are likely and costly, prove each behavior at the lowest layer that can, keep tests independent and focused on observable behavior, cover regressions and boundary cases, and name and run tests for clear feedback.

**When to read this group:** When adding or changing behavior, fixing a bug, or writing, running, and reviewing tests.

### Choose tests by risk and cost

Rule ID: `fabrica:practices/testing/choose-tests-by-risk`

Version: 1.0.1

**When to read:** Before planning, writing, or reviewing the tests for a change, or deciding whether an existing test is worth keeping, such as when adding a feature, changing complex logic, or pruning a slow or brittle suite.

**Impact:** HIGH

**Why it matters:** Spreading test effort evenly or chasing coverage leaves risky behavior unguarded while low-value tests slow every change.

**Read full rule:** [Choose tests by risk and cost](../../rules/fabrica/practices/testing/choose-tests-by-risk.md)

### Cover empty inputs and boundaries

Rule ID: `fabrica:practices/testing/cover-boundary-cases`

Version: 1.0.1

**When to read:** Before planning, writing, changing, or reviewing code or tests that process collections, check ranges or thresholds, compute positions, or relate two items, such as validation limits, pagination, sorting, or moving items in a list or tree.

**Impact:** MEDIUM

**Why it matters:** Catches bugs at the edges, which tests that use only ordinary inputs never reach.

**Read full rule:** [Cover empty inputs and boundaries](../../rules/fabrica/practices/testing/cover-boundary-cases.md)

### Keep tests independent

Rule ID: `fabrica:practices/testing/keep-tests-independent`

Version: 1.0.1

**When to read:** Before planning, writing, debugging, or reviewing automated tests that share data, global state, or services, such as tests against a shared database, browser tests that run in parallel workers, tests that change configuration or the clock, or tests that call external services.

**Impact:** MEDIUM-HIGH

**Why it matters:** Tests that depend on each other or on live services fail intermittently or pass by accident, which makes every failure harder to trust and diagnose.

**Read full rule:** [Keep tests independent](../../rules/fabrica/practices/testing/keep-tests-independent.md)

**Impact:** LOW

### Run focused tests while iterating, and the full suite before finishing

Rule ID: `fabrica:practices/testing/run-focused-tests-while-iterating`

Version: 1.0.1

**When to read:** Before running tests during implementation, debugging, or review, or before declaring a change complete.

**Impact:** LOW-MEDIUM

**Why it matters:** Running the whole suite on every edit slows feedback, while stopping after one passing test misses breakage elsewhere.

### Test at the lowest layer that proves the behavior

Rule ID: `fabrica:practices/testing/test-at-the-lowest-layer`

Version: 1.0.1

**When to read:** Before planning, writing, or reviewing a test and choosing whether it should be a unit, integration, or end-to-end test, including regression tests for bug fixes.

**Impact:** MEDIUM-HIGH
