## ✨ New Features

### Sources can follow branches

- A source can now follow a branch, such as `main`, so your project gets a library's or skill repository's newest work without waiting for a release. (#144)
- Trail Guide warns you when what you take from a branch isn't in a library release yet.

### Fork a skill

- When a library's skill is close to what you want, you can now fork it into your library or project and edit your copy. (#145)
- Trail Guide remembers where the fork came from and later shows you what changed in the original, so you can bring those changes in.

### Programmatically start a new skill

- You can now have your agent create a new skill programmatically by calling `trailguide library add skill NAME` and `trailguide project add skill NAME`. These commands will write a draft skill for you to fill in, so you don't have to set up its folder and file by hand. (#147)

### Leave out skills by level

- A project can now take only the skills a library requires, or skip the ones it recommends, without listing each skill by name. (#148)

### Better handling when skills depend on other skills

- A library's skill can now rely on a skill that the library takes from another repository.
- Projects that install a skill get the dependent skill too, so it works without extra setup. (#143)

## ⬆️ Improvements

- `trailguide project update --help` now explains how skills update, and naming a skill as an update target tells you to update its source instead. (#146)
- When a skill's level changes, the `trailguide project update` preview now shows the change on that skill's row instead of a separate row. (#149)
- The docs homepage plays a narrated tour of Trail Guide. (#137)
