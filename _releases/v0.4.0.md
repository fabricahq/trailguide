## ✨ New Features

### Code Rules is now Trail Guide

As you'll see in a moment, we now support managing both skills and rules together. In addition, it's become clear that both skills and rules go beyond merely coding and extend to writing tests, designing architectures, and more. Given both of those insights, the name "Code Rules" was fast aging.

Every time your agent builds something, it's walking a "trail" it hasn't walked before. It needs guidance to get where it's going, and Trail Guide delivers the skills and rules it needs to get where it's going.

### We now support managing skills

Trail Guide now manages your agents' skills the way it manages rules, so every developer and agent on a project uses the same reviewed skills. Name the skills you want from each source, and `trailguide project sync` installs them into the folders your agents read:

```yaml
schemaVersion: 2
skillTargets: [claude, agents]
sources:
  fabrica:
    repository: https://github.com/fabricahq/public-rules.git
    rules: {include: [techs/go/*]}
    skills: {include: [skills/build-feature]}
```

- Install skills for Claude, for other agents, or both.
- Install skills from any Git repository, not only rule libraries.
- Skills automatically bring along the skills and rules they use. (#124)
- Leave out any skill, or fork it to make it your own. (#125)
- Libraries can require skills in every project and curate skills from other repositories. (#133, #134, #139)
- Skills with the same name can install side by side. (#132)

See [Install skills](https://trailguide.fabricahq.com/guides/install-skills/). (#120, #123)

### Also new

- Trail Guide keeps a short section in your `AGENTS.md` that points agents at your rules and skills, and leaves the rest of the file alone. (#127, #128)
- Choose rules by ID, by group, or by type, and pick up rules a library adds to a group later. (#117)
- Projects and libraries share one layout, so one repository can be both. (#118, #119)

## ⬆️ Improvements

- Before an update, Trail Guide shows which skills change and flags new or changed scripts to review. (#122)
- Trail Guide warns when a personal skill has the same name as one your project installs. (#121)
- Five new standard practice groups, including architecture, debugging, and writing. (#111)
- Trail Guide detects and repairs edited or missing installed skills, and checks a library's skills. (#123)

## 🐛 Squashed Bugs

- Release binaries are now built with Go 1.27.2, which fixes the standard library vulnerability [GO-2026-6604](https://pkg.go.dev/vuln/GO-2026-6604). (#113)

## ⛓️‍💥 Breaking Changes

This release renames Code Rules to Trail Guide, with the `trailguide` CLI, the `.trailguide/` directory, the `<org>/.trailguide` library convention, and `trailguide_<version>_<os>_<arch>.tar.gz` release archives; requires version 2 project configuration; moves a project's own rules from `local/` to `rules/` and a library's `rule-library.yaml` and groups into `.trailguide/`; replaces `project add library` with `project add source`; and changes the managed `.trailguide/README.md` guide. Because Trail Guide is in initial development and hasn't been publicly announced, we're not including upgrade instructions. (#117, #118, #119, #120, #126, #128, #138)

Compatibility with what Code Rules wrote:

- Project commands still work in `.code-rules/` and warn you to run `git mv .code-rules .trailguide`.
- Library commands refuse to run until you run `git mv .code-rules .trailguide`.
- Library releases published from `.code-rules/` stay readable, so projects keep their rule versions.
- Library releases in the earlier layout, with `rule-library.yaml` and groups at the repository root, can't be imported: `trailguide project sync` and `update` fail with `unsupported-library-layout` until the library publishes a library release from the new layout.
- `trailguide project init`, `build`, `sync`, and `update` replace an older, unedited managed guide with the new one, but refuse to overwrite one you edited.

**Go importers:** the module path moved from `github.com/fabricahq/code-rules` to `github.com/fabricahq/trailguide`, and the `coderules` package is now `trailguide`. Import `github.com/fabricahq/trailguide/trailguide` instead of `github.com/fabricahq/code-rules/coderules`. (#126, #138)
