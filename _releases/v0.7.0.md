## ✨ New Features

### Library releases now version skills

- Before, a library release versioned only rules, so a project couldn't tell which of a library's skills had changed or how. Now each library release gives every skill its own version and change notes, and its release notes name each skill's version, level, and fork. (#162)
- Learn more in [Skills in the release record](https://trailguide.fabricahq.com/reference/rule-versions/#skills-in-the-release-record).

### We've consolidated to one lockfile

- Projects now record every source's ref, commit, library release, rule and skill versions, and file digests in a single lock file: `.trailguide/lock.json`. Previously, we had both `provenance.json` and one `_source.json` per rule. (#166, #168)
- Learn more in [Inspect the lockfile](https://trailguide.fabricahq.com/reference/provenance/#inspect-the-lockfile).

### Libraries now declare a library config format

- Before, a project that imported a library also validated the library's own project configuration, so a setting the library used for itself could potentially stop the import. Now a library declares `library.formatVersion: 1`, and projects and tools such as [Rulemart](https://rulemart.fabricahq.com) read only what the library publishes. A tool can now detect a library in a format it doesn't read and skip just that library. (#167)
- Learn more in [Library format](https://trailguide.fabricahq.com/reference/library-format/#library-format).

## ⬆️ Improvements

- A replacement rule's page now names the rule it replaces, its base version, and the reason. (#168)

## ⛓️‍💥 Breaking Changes

Because Trail Guide is in initial development and hasn't been publicly announced, we're not including upgrade instructions.

### Library sources need a ref

A library source must now set `ref` to a library release such as `release/4`, to `latest-release`, or to a branch, and sync fails with `ref-required` when it's missing. `latest-release` and branches now move only when you run `project update`. (#163)

### The lockfile replaces `_source.json` and `provenance.json`

Projects now keep their source records in `.trailguide/lock.json` instead of `vendor/<source>/_source.json`, and Trail Guide no longer writes `generated/provenance.json`; the first sync migrates a project. (#166, #168)

### Libraries must declare `formatVersion: 1`

Every library must now set `library.formatVersion: 1`, and projects can't import a library release without it. Earlier Trail Guide versions reject the field, so a library adds it when it moves to this release. The `trailguide` Go package now returns `UnsupportedLibraryFormatError` for a library in another format. (#167)

### Skill changes need change notes

After a library's first library release, a new, changed, or retired skill now needs a change note, as a rule does. (#162)
