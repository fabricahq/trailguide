## ⬆️ Improvements

- `trailguide project update` now asks every question in a terminal as yes or no, or y or n, so the same answer works for every question; before, each kind of question took its own pair of answers, such as adopt or keep and add or exclude. Learn more in [Update rules and skills](https://trailguide.fabricahq.com/guides/update/). (#189)
- A project that still keeps skill folders directly in `.trailguide/skills/`, as projects did before v0.9.0, now fails as soon as any project command reads it, before update asks anything. The error now lists every folder to move, with the files it bundles, the origin folder it belongs in, and how to fix links to it. Learn more in [Skill folders](https://trailguide.fabricahq.com/reference/skill-format/#skill-folders). (#189)
- Library release notes now include a **Library schema** section when a library moves to a new library schema version, so projects know to check that their Trail Guide supports it before they update. Learn more in [GitHub Release pages](https://trailguide.fabricahq.com/reference/rule-versions/#github-release-pages). (#191)
